# Пререндер для SEO

Пререндер превращает CSR SPA в полноценные статические HTML-страницы,
которые видит Яндекс/Google **без выполнения JavaScript**.

## Как это работает

При обычной сборке CRA у нас был один `build/index.html`, и все маршруты
(`/faq`, `/ceny`, `/remont-printerov-hp`…) отдавали этот же файл. Яндекс
видел одинаковый контент на всех страницах → индексировал 3-4 из 24.

Теперь `npm run build` автоматически запускает `scripts/prerender.mjs`,
который через headless Chrome посещает каждый маршрут и сохраняет
результирующий HTML в отдельный файл:

```
build/index.html                      ← главная
build/faq/index.html                  ← FAQ (уникальный title, description, JSON-LD)
build/ceny/index.html                 ← цены
build/remont-printerov-hp/index.html  ← ремонт HP
… всего 24 страницы
```

## Требования

- Node.js ≥ 20
- ~200 МБ на диске (Puppeteer скачает Chromium при `npm install`)

## Использование

```bash
# Обычный билд + автоматический пререндер:
npm run build

# Только пререндер (если билд уже готов):
npm run prerender
```

После `npm run build` смело загружайте всю папку `build/` через FASTPANEL —
никаких дополнительных действий не требуется.

## Настройка сервера (nginx)

Убедитесь, что nginx для URL `/faq`, `/ceny` и т.д. отдаёт
соответствующий поддиректории `index.html`, а не только корневой:

```nginx
location / {
  # Сначала пробуем точный файл, потом папку с index.html, только потом SPA-fallback.
  try_files $uri $uri/index.html $uri/ /index.html;
}
```

Ключевое отличие от обычной SPA-конфигурации — `$uri/index.html` в списке.

## Если что-то пошло не так

- **Chromium не скачался** — установите вручную: `npx puppeteer browsers install chrome`
- **Использовать системный Chrome** — задайте переменную окружения:
  `PUPPETEER_EXECUTABLE_PATH=/usr/bin/google-chrome npm run build`
- **Изменился список маршрутов** — правьте массив `ROUTES` в
  `scripts/prerender.mjs`
- **Пререндер отвалился на одной странице** — остальные всё равно
  успешно генерируются; посмотрите вывод скрипта на ошибки

## Что делать с индексацией

После загрузки на прод:

1. Проверить любой URL через `curl`:
   ```bash
   curl -A "YandexBot/3.0" https://complexprint.ru/faq | grep '<title>'
   ```
   Должен вернуться title, специфичный для FAQ, а не общий.

2. В Яндекс.Вебмастере: **Инструменты → Проверка ответа сервера** —
   вбить URL, увидеть, что реально возвращается.

3. В Яндекс.Вебмастере: **Индексирование → Переобход страниц** —
   отправить обновлённый sitemap и запустить принудительный обход
   ключевых URL.

4. Через 2-4 недели `site:complexprint.ru` должен показывать все 24
   страницы вместо 7.
